# 小程序发布检查清单

## 使用说明

- 代码门禁：执行 `npm run check`。
- 生产声明门禁：在本机证据真实完成后执行 `npm run check:release:production`。
- 生产部署、权限、隐私、双账号、真机与提醒触达必须分别记录为 `PASS / FAIL / BLOCKED`；环境变量为 `true` 不能替代截图、日志或测试记录。

## 代码配置

- `project.config.json` 中替换正式 `appid`。
- `miniprogram/app.js` 中填写正式云开发 `ENV_ID`。
- 上传并部署云函数：`login`、`healthApi`、`paymentApi`、`adminApi`、`reminderDispatcher`，并上传健康待办定时触发器。
- 配置健康待办订阅模板 ID、字段映射、正式版跳转环境和 `reminders` 复合索引。
- 小程序后台配置服务类目和隐私协议。

## 数据与隐私

- 数据库集合按 `docs/wechat-cloud-database.md` 创建。
- 家庭健康数据必须在隐私政策中说明用途。
- 图片上传涉及处方、检查单、外包装说明书，必须提示用户谨慎上传个人敏感信息。
- 后台日志不得输出完整健康记录、医嘱、用药详情。

## 医疗安全边界

发布版本必须保留统一提示：

> 本系统仅用于家庭健康记录、历史信息查询和医嘱整理，不提供疾病诊断、处方建议或剂量调整建议。用药请遵医嘱或咨询医生/药师；如症状加重或出现紧急情况，请及时就医。

AI 功能不得输出：

- 诊断结论
- 处方推荐
- 剂量调整
- 停药、换药、替代药建议
- “不用去医院”之类承诺

## 测试路径

1. 新用户首次进入只创建用户；首次记录病程或添加药品时按需创建家庭。
2. 添加家庭成员。
3. 添加药品。
4. 拍外包装照片并保存药品。
5. 新增健康记录并上传一张检查单或处方图片。
6. 记录一次用药，确认药品剩余量扣减。
7. 确认图片整理功能关闭时，药品编辑页不显示“图片整理暂未开放”入口。
8. 从病程详情添加健康待办，确认成员和病程已自动关联；接受订阅授权后等待到期消息并验证跳转。
9. 对待接受的家庭邀请点击“继续分享”，确认沿用原邀请链接且不会重复创建邀请。
10. 在药品详情重新打开已保存图片，确认图片正常回显。
11. 在用药记录页确认“修改”和“作废”按钮尺寸紧凑且原操作正常。
12. 导出家庭数据和就医沟通记录。
13. 进入会员中心，确认不显示套餐价格、购买渠道或支付入口；输入会员兑换码并完成权益激活。
14. 确认 Web 管理后台能看到用户、家庭、药品、记录、附件、订单、会员家庭、优惠券和 AI 用量。

## 管理后台

独立 Web 管理后台见 `docs/web-admin.md`。

上线前必须创建 `admins` 集合，并绑定 CloudBase Web Auth 管理员 UID：

```json
{
  "authUid": "CloudBase Auth 用户 UID",
  "role": "owner",
  "status": "active",
  "name": "管理员名称"
}
```

管理后台当前统计：

- 用户数
- 家庭数
- 家庭成员数
- 药品数
- 健康记录数
- 用药记录数
- 附件数
- 提醒数
- 快过期药品
- 低库存药品
- 订单数
- 付费订单数
- 会员家庭数
- 优惠券数
- 优惠券核销数
- AI 用量

Web 管理后台上线前必须配置：

- `VITE_CLOUDBASE_ENV_ID`
- `VITE_CLOUDBASE_REGION`
- `VITE_CLOUDBASE_PUBLISHABLE_KEY`
- `ADMIN_WEB_AUTH_E2E_PASSED=true`，仅在真实管理员和非管理员账号验收完成后填写

## GitHub 发布

推送前执行：

```bash
npm run check
npm run check:release:production
```

如仓库没有远程地址：

```bash
git remote add origin <你的 GitHub 仓库地址>
git push -u origin master
```

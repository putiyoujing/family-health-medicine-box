# 后台退款规则与验收（2026-10-22）

## 已确定的产品规则

- 小程序前台不给退款申请入口，只展示订单状态；购买文案说明虚拟服务不支持在前台申请退款。
- 仅后台主管理员可以发起退款；输入金额须大于 0，且不得超过这笔订单实际支付金额。
- 部分退款与全额退款都关闭该订单，回收该订单带来的全部会员权益；之后的续费和兑换权益保留。
- iOS 订单不走后台主动退款；当前 iOS 支付继续关闭。

## 代码路径与安全边界

Web 后台订单表的退款按钮只对已支付的虚拟支付订单启用。`adminApi` 验证主管理员、金额和平台实付及可退余额后，创建唯一退款单号并向微信申请。申请发出后先标为 `refunding`；接口返回受理或网络超时都不能当作到账成功，也不能重新生成退款单号。`paymentApi` 通过可信退款通知或定时查退款单核实最终结果，核实后以数据库事务同时更新订单、原权益记录、后续权益时间和家庭会员状态。未核实前权益仍有效。未知状态、记录不一致或超过安全处理上限时保留待核查状态，禁止静默回收。

## 已完成的本地验证

- 退款金额 0、负数、超实际支付、非整数分被拒；同单重复申请被拒。
- 微信退款申请使用现网 `env=0`、新退款单号、整数分和按请求原文签名；查单要求订单号、平台单号、实付与剩余可退金额一致。
- 退款未完成时不回收权益；部分退款成功时整笔订单权益被撤销；之后续费及兑换权益的有效期重算并保留。
- 可信回调须匹配本地退款单，并再次向微信查证成功；不匹配的通知不改订单。
- 小程序订单页没有退款申请操作。

## 生产验收仍需完成

1. 发布四个微信虚拟道具，录入对应商品 ID 和正式支付密钥；`paymentApi` 与 `adminApi` 均需支付侧配置。不要把密钥写入仓库或聊天。
2. 部署两支云函数并提高超时，配置发货与退款推送、五分钟查单触发器和 `orders` 查询索引。
3. 在 Android 真机完成一笔预算内真实支付，检查支付、发货、后台订单与会员状态一致。
4. 后台对该笔订单发起不超过实付额的退款，保存微信退款单、通知/查单、订单关闭与权益回收证据。另用隔离数据验证“先续费/兑换，后退早期订单”。
5. `WECHAT_VIRTUAL_PAYMENT_REFUND_E2E_PASSED` 只能在真实平台退款及权益链路验收后填写为 `true`。

当前仅有本地模拟与静态检查证据，**退款链路尚未达到可上线状态**。[微信云开发虚拟支付指引](https://docs.cloudbase.net/integration/wechat-virtual-pay)要求道具价格匹配、可信回调与真实设备验证；[腾讯云开发虚拟支付参考](https://github.com/TencentCloudBase/CloudBase-AI-Toolkit/blob/main/config/source/skills/cloudbase-wechat-integration/references/virtual-payment.md)区分 Android 主动退款与 iOS 由 Apple 处理。

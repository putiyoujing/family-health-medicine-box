# 初始化状态操作逻辑与测试矩阵

## 目标

保证用户第一次打开小程序、没有真实云数据、只有创建者本人档案、没有药品、没有病程记录时，每一个入口都有明确的下一步，不出现空选择器、无效保存、静默失败或误以为已经记录成功。

当前开发测试版本默认开启 `ENABLE_DEV_MOCK_LOGIN`。仅在微信开发者工具模拟器中启动时，会跳过 `wx.login()` 和云函数，直接使用本地测试身份完成登录；iOS/Android 真机即使使用开发版，也会连接真实 CloudBase 环境和云函数：

- `openid`: `devtools-openid`
- `nickname`: `测试用户`
- `currentFamilyId`: `demo-family-001`
- `loginMode`: `test`

该开关只对 `envVersion=develop` 且运行平台为 `devtools` 生效，体验版、正式版和真实设备会强制走真实登录。需要在开发者工具模拟器中联调真实登录时，把 `miniprogram/app.js` 顶部的 `ENABLE_DEV_MOCK_LOGIN` 临时改为 `false`，并配置云环境。

## 全局状态机

1. 未启动
2. 启动中：识别当前小程序版本
3. 登录中：
   - 开发版 Mock 模式：跳过微信接口，落到测试用户
   - 真实登录模式：调用 `wx.login()` 和 `login` 云函数，创建或读取用户
4. 已登录：
   - 允许读取首页、个人中心、家庭空间、会员、药箱、健康记录
   - 所有 `api` 调用仍会二次确认登录，防止页面漏判
5. 登录失败：
   - 页面弹窗提示“需要微信登录”
   - 用户可点“重新登录”

## 初始化数据规则

新用户注册后只创建用户账号，不自动创建家庭空间。真实初始化通常是：

- 有用户
- 没有家庭、家庭角色和家庭成员档案
- `currentFamilyId` 为空

用户可以先接受家人邀请加入已有家庭，也可以在首次明确点击“记录病程/添加药品”时按需创建家庭。按需创建会一次性创建家庭、创建者本人档案和 owner 角色，然后继续原操作。

线上已有 `families` / `family_roles` 数据的用户视为已经完成默认家庭创建，不迁移、不重建，继续按原家庭使用。产品逻辑仍保留“无家庭空间”的兜底判断，避免新用户、被移出家庭的用户或历史脏数据出现断路。

## 操作门禁

| 功能入口 | 必要条件 | 不满足时的处理 |
| --- | --- | --- |
| 个人中心首页 | 已登录 | 弹窗要求微信登录 |
| 查看/修改个人信息 | 已登录 | 弹窗要求微信登录 |
| 添加家庭成员 | 已登录 + 有家庭空间 | 未登录先登录；无家庭先创建或加入家庭 |
| 记一次生病 | 已登录 + 可编辑家庭 + 至少 1 个家庭成员 | 无家庭时先按需创建并生成“本人”档案；有家庭但无成员时引导添加成员 |
| 记录一次用药 | 已登录 + 有家庭空间 + 至少 1 个成员 + 至少 1 个药品 | 记录用药本身不自动创建家庭；缺家庭先创建或加入，缺成员先引导添加，缺药品则跳转到独立的添加药品页 |
| 从病程详情记录用药 | 同“记录一次用药” | 满足后直接打开用药二级表单并带上病程和成员；不满足则先补基础资料 |
| 药箱添加药品 | 已登录 + 有家庭空间 | 成员可选，默认全家通用 |
| AI 助手 | 已登录 | 未登录先登录；可在空数据下回答“暂无记录”类内容 |
| 导出报告 | 已登录 | 未登录先登录；空数据生成空摘要或提示无记录 |
| 会员中心/兑换会员码 | 已登录；兑换需要有家庭空间 | 未登录先登录；无家庭可查看权益，但兑换前需先创建或加入家庭 |
| 家庭邀请/切换 | 已登录 | 未登录先登录；无自有家庭也可以接受他人邀请 |
| 创建家庭 | 已登录 + 未达到账号创建额度 | 已有线上家庭按已创建计入额度；受邀加入的家庭不计入自有创建额度 |
| 图片解析 | 已登录 + 已上传图片 | 未上传图片提示先上传 |

## 推荐的新用户路径

1. 第一次打开首页：自动完成微信/测试登录。
2. 用户可以直接为“本人”记录一次生病。
3. 如果要记录孩子、老人等其他家人，先进入家庭管理添加成员。
4. 保存其他成员后，可以从成员列表发起本人邀请并选择查看者、协作者或管理员权限。
5. 用户点“记录一次用药”：
   - 没有成员：先添加成员
   - 有成员但没有药品：跳药箱并打开独立的添加药品页
6. 用户保存药品后，从用药列表进入二级表单，记录剂量、时间和反应并扣库存。

## 开发实现原则

- 页面层做用户体验门禁：弹窗、跳转、自动打开表单。
- 服务层做安全兜底：所有 `api` 调用先确认登录。
- 后端继续做权限校验：家庭角色、记录归属、配额限制不能只靠前端。
- 初始化空态优先引导“下一步动作”，不要让用户面对空 picker 或保存失败才知道缺什么。

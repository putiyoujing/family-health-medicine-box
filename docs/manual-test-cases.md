版本日期：2026-07-19
适用项目：`family-health-medicine-box`
测试目标：验证“记录一次生病 → 追加病程时间线 → 关联用药 → 生成复诊摘要”的首发主链路，同时覆盖药箱、附件、家庭共享、会员兑换、管理后台、隐私和真实环境门禁。

## 1. 先看这里：怎么执行

不要只在开发者工具的演示数据里点一遍。完整验收分三轮：

| 轮次 | 环境 | 目的 | 可否判定上线 |
| --- | --- | --- | --- |
| A | 微信开发者工具，开发版 Mock 模式 | 快速检查页面、表单、跳转和主流程 | 否，只能判定演示流程 |
| B | 真实微信云开发环境，关闭 Mock | 检查登录、数据库、云存储、云函数、权限和持久化 | 可判定云端功能是否通过 |
| C | 两个微信账号 + iOS/Android 真机 | 检查家庭共享、越权、授权、隐私、网络和设备体验 | 是，正式发布必测 |

推荐顺序：先执行第 5 节“黄金主流程”，再执行第 6～15 节的独立回归用例。

### 1.1 结果填写规则

- `PASS`：实际结果与预期完全一致，并留有证据。
- `FAIL`：实际结果与预期不一致。
- `BLOCKED`：因云环境、账号、设备或外部配置缺失而无法执行；不能算通过。
- `N/A`：本次版本明确不包含的功能；必须在备注中写明原因。

每个失败项至少记录：用例编号、设备/基础库版本、账号角色、操作步骤、实际结果、截图或录屏、发生时间。

## 2. 当前版本边界

以下是当前产品的真实边界，测试时不要把“明确提示未开放”误判为故障，也不要把模拟流程误判为正式能力：

1. 开发版默认 `ENABLE_DEV_MOCK_LOGIN=true`，只在 `envVersion=develop` 时使用测试身份和演示数据。
2. 体验版、正式版必须走真实微信登录和云函数，不允许回退到演示数据。
3. 图片可以安全上传；真实 OCR/AI 图片整理当前未启用。正确行为是明确提示“暂未开放”，不能生成伪识别结果。
4. 健康待办代码已支持关联成员/病程和微信一次性订阅消息；未配置模板 ID、字段映射、定时触发器或真机授权时必须记为 `BLOCKED`，不能声称消息已接入生产。
5. 首发阶段不在小程序内支付，只通过官方渠道发放会员兑换码。
6. GitHub Pages/Web 静态后台只能展示演示数据；生产真实数据必须经过可信管理员登录网关。
7. AI 只整理当前家庭已有记录，不得诊断、开药、调剂量、建议停药或承诺“不用就医”。

## 5. P0 黄金主流程（必须完整连续执行）

### TC-E2E-001：从新用户到复诊摘要

**优先级**：P0
**环境**：B 真实云环境；最后在 C 真机各复测一次
**前置条件**：账号 A 从未进入该测试环境；该账号在 `users/families/family_roles` 中没有残留测试数据。
**成功标准**：全链路无中断；前台、重新进入后的持久化数据、云数据库关联关系一致；摘要只包含用户输入或已确认的数据。

## 17. 最终放行标准

### 17.1 封闭测试 GO

必须同时满足：

- TC-E2E-001 全部通过。
- 所有 P0 本地/真实云可执行用例通过。
- S1/S2 缺陷为 0。
- 图片识别、提醒、支付等未开放能力均有真实、清楚、不误导的提示。
- 自动检查 `npm run check` 通过。

### 17.2 正式上线 GO

除封闭测试标准外，还必须满足：

- 正式 `ENV_ID` 已配置。
- 五个云函数、健康待办定时触发器和所有必需集合/索引已正式部署。
- 敏感集合全部确认 `ADMINONLY`。
- 微信《用户隐私保护指引》覆盖所有实际使用的隐私 API。
- 双账号家庭共享、角色权限、跨家庭越权用例全部通过。
- iOS 和 Android 真机矩阵通过。
- 可信管理员登录网关已部署，生产后台安全用例通过。
- `npm run check:release:production` 通过。

# 三角色评估与缺口计划

更新时间：2026-05-12

## 产品经理视角

### 完整性判断

当前项目已经具备家庭健康药箱小程序的核心闭环：

- 用户进入后创建家庭空间。
- 添加家庭成员。
- 添加药箱药品。
- 记录生病过程。
- 记录一次用药并扣减库存。
- 上传检查单/处方图片。
- 基于已有记录做 AI 安全查询。
- 管理后台查看用户、家庭、药品、记录、附件和风险统计。

### 竞争性判断

相较普通备忘录、相册和表格，当前差异点是：

- 家庭成员、药品、病程、用药之间有结构化关联。
- 用药记录会自动影响库存。
- AI 查询只做历史整理，不越界做诊断和处方。
- 管理后台能看数据质量和运营风险。

### 产品缺口

- 家庭邀请与多人协作还未完成。
- OCR 只是上传占位，尚未自动识别处方/检查单。
- DeepSeek 还未真实接入，目前是规则型安全查询。
- 提醒还没有推送订阅消息。
- 缺少真实用户引导和首次示例数据。

### 结论

可以作为封闭测试 MVP，但还不建议直接开放大规模公开发布。下一阶段优先补：家庭邀请、OCR、订阅提醒、真实 AI 整理。

## 项目经理视角

### 完整性判断

当前工程结构清楚：

- 小程序前端：`miniprogram/`
- 业务云函数：`cloudfunctions/healthApi`
- 登录云函数：`cloudfunctions/login`
- 管理后台云函数：`cloudfunctions/adminApi`
- 发布文档：`docs/`

### 交付风险

- 真实 `appid` 与 `ENV_ID` 未配置。
- 云数据库集合、索引、权限需在微信云开发控制台创建。
- 云函数依赖需在微信开发者工具中部署。
- 医疗相关隐私政策、服务类目、审核材料需要准备。
- GitHub 已推送私有仓库，但不是微信侧发布。

### 结论

代码仓库已达到“可进入微信开发者工具联调”的状态。发布前需要完成云环境配置和真机测试。

## 测试经理视角

### 已验证

- 云函数和小程序 JS 通过 `node --check`。
- Web 原型通过 `npm run build`。
- Web 原型通过 `npm run lint`。
- GitHub 推送成功。

### 未验证

- 微信开发者工具编译。
- 云函数真实部署。
- 微信云数据库读写。
- 云存储上传。
- 真机授权、网络、隐私弹窗。
- 管理员白名单权限。

### 必测用例

1. 新用户首次进入，自动创建用户和家庭。
2. 添加家庭成员。
3. 添加药品，验证列表显示。
4. 新增生病记录。
5. 上传检查单或处方图片，验证云存储 fileId。
6. 记录用药，验证库存自动扣减。
7. AI 查询快过期药品。
8. AI 查询诊断类问题，验证拒答。
9. 非管理员进入管理后台，验证无权限。
10. 管理员进入管理后台，验证统计和列表。
11. 导出家庭数据。

### 结论

自动化代码检查已完成，但微信环境联调尚未完成。上线前必须走完整真机测试。

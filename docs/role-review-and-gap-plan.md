# 三角色评估与缺口计划

更新时间：2026-05-12

## 产品经理视角

### 完整性判断

当前项目已经具备「家人健康记」家庭健康管理工具的核心闭环：

- 用户进入后创建家庭空间。
- 添加家庭成员。
- 添加家庭药箱药品。
- 记录健康情况。
- 记录一次用药并扣减库存。
- 上传检查单/处方图片。
- 拍外包装/说明书并关联药品。
- 图片整理确认页，解析结果经用户确认后保存。
- 基于已有记录做 AI 安全查询。
- 家庭共享邀请、角色管理和家庭切换。
- 会员中心、优惠券、订单和支付确认。
- 提醒管理与就医沟通记录导出。
- 独立 Web 管理后台查看用户、家庭、药品、记录、附件和风险统计。

### 竞争性判断

相较普通备忘录、相册和表格，当前差异点是：

- 家庭成员、药品、健康记录、用药之间有结构化关联。
- 用药记录会自动影响库存。
- AI 查询只做历史整理，不越界做诊断和处方。
- 图片解析结果不自动入库，需要用户确认，降低健康数据误写风险。
- 管理后台能看数据质量和运营风险。

### 产品缺口

- DeepSeek 或 OCR 图片识别服务尚未接入真实密钥，当前为图片上传、任务记录和确认保存闭环。
- 微信支付或虚拟支付尚未接入真实商户配置，当前为订单、优惠券和支付确认闭环。
- 微信订阅消息模板尚未配置，当前已完成提醒记录管理。
- 缺少真实用户引导和首次示例数据。

### 结论

可以作为封闭测试 MVP，但还不建议直接开放大规模公开发布。下一阶段优先补：真实图片识别、真实支付、订阅消息和新手引导。

## 项目经理视角

### 完整性判断

当前工程结构清楚：

- 小程序前端：`miniprogram/`
- 业务云函数：`cloudfunctions/healthApi`
- 登录云函数：`cloudfunctions/login`
- 管理后台云函数：`cloudfunctions/adminApi`
- 支付云函数：`cloudfunctions/paymentApi`
- 独立 Web 管理后台：`src/`
- 发布文档：`docs/`

### 交付风险

- 真实 `appid` 与 `ENV_ID` 未配置。
- 云数据库集合、索引、权限需在微信云开发控制台创建。
- 云函数依赖需在微信开发者工具中部署。
- 医疗相关隐私政策、服务类目、审核材料需要准备。
- GitHub 已推送私有仓库，但不是微信侧发布。

### 结论

代码仓库已达到“可进入微信开发者工具联调”的状态。发布前需要完成云环境配置和真机测试。

## 测试经理视角

### 已验证

- 云函数和小程序 JS 通过 `node --check`。
- Web 原型通过 `npm run build`。
- Web 原型通过 `npm run lint`。
- GitHub 推送成功。

### 未验证

- 微信开发者工具编译。
- 云函数真实部署。
- 微信云数据库读写。
- 云存储上传。
- 真机授权、网络、隐私弹窗。
- Web 管理后台 token 与管理员权限。
- 真实图片识别服务。
- 真实微信支付或虚拟支付。
- 微信订阅消息推送。

### 必测用例

1. 新用户首次进入，自动创建用户和家庭。
2. 添加家庭成员。
3. 拍外包装照片并添加药品，验证列表显示。
4. 新增健康记录。
5. 上传检查单或处方图片，验证云存储 fileId。
6. 进入图片整理确认页，验证结果不会自动写入业务记录。
7. 记录用药，验证库存自动扣减。
8. 创建家庭邀请，另一个用户接受邀请并切换家庭。
9. 进入会员中心，选择优惠券并完成支付确认。
10. 添加用药提醒或复诊提醒。
11. AI 查询快过期药品。
12. AI 查询诊断类问题，验证拒答。
13. 导出家庭数据和就医沟通记录。
14. Web 管理后台验证统计和列表。

### 结论

自动化代码检查已完成，但微信环境联调尚未完成。上线前必须走完整真机测试。

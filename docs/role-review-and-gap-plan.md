# 三角色评估与缺口计划

更新时间：2026-07-24

## 当前总评

1.0.12 已具备完整业务代码、自动化门禁、生产 CloudBase 函数/集合权限/托管/触发器基线。当前最大的发布风险不是继续补功能，而是生产密钥轮换和真实验收证据没有形成可审计交付物。

## 产品经理视角

### 完整性判断

当前项目已经具备「家人健康记」家庭健康管理工具的核心闭环：

- 用户进入后创建家庭空间。
- 添加家庭成员。
- 添加家庭药箱药品。
- 记录健康情况。
- 记录一次用药并扣减库存。
- 上传检查单/处方图片。
- 拍外包装/说明书并关联药品。
- 图片整理确认页，解析结果经用户确认后保存。
- 基于已有记录做 AI 安全查询。
- 家庭共享邀请、角色管理和家庭切换。
- 会员中心、优惠券、订单和支付确认。
- 健康待办与就医沟通记录导出。
- 独立 Web 管理后台查看用户、家庭、药品、记录、附件和风险统计。

### 竞争性判断

相较普通备忘录、相册和表格，当前差异点是：

- 家庭成员、药品、健康记录、用药之间有结构化关联。
- 用药记录会自动影响库存。
- AI 查询只做历史整理，不越界做诊断和处方。
- 图片解析结果不自动入库，需要用户确认，降低健康数据误写风险。
- 管理后台能看数据质量和运营风险。

### 产品缺口

- 图片识别默认关闭；开放前需补服务、成本、失败降级和用户确认验收。
- 真实支付不在首发范围，1.0.12 使用兑换码完成会员交付。
- 提醒代码、生产函数和每分钟触发器已完成；仍缺真实消息触达证据。
- 新用户引导和空状态可继续优化，但不能用伪造的生产数据代替。

### 结论

可以作为发布候选版本。P0 顺序为密钥轮换、隐私/双账号/真机/提醒证据、微信审核；图片识别和真实支付进入后续版本。

## 项目经理视角

### 完整性判断

当前工程结构清楚：

- 小程序前端：`miniprogram/`
- 业务云函数：`cloudfunctions/healthApi`
- 登录云函数：`cloudfunctions/login`
- 管理后台云函数：`cloudfunctions/adminApi`
- 支付云函数：`cloudfunctions/paymentApi`
- 健康待办派发云函数：`cloudfunctions/reminderDispatcher`
- 独立 Web 管理后台：`src/`
- 发布文档：`docs/`

### 交付风险

- Git 全历史未发现 AppSecret 泄漏；项目负责人决定延期轮换，正式发布前仍建议完成。
- 隐私、双账号、iOS/Android 真机和提醒触达缺少持久证据。
- Web 管理后台首包约 976 KB；部分查询上限 100 条；云函数 Node.js 16.13 运行时需要后续治理。
- GitHub 合并、标签和 Release 只是代码发布，不能替代微信侧审核与上线。

### 结论

代码仓库和生产云资源已达到候选发布状态；微信侧公开发布仍以 P0 证据和审核结果为准。

## 测试经理视角

### 已验证

- 云函数和小程序 JS 通过 `node --check`。
- Web 原型通过 `npm run build`。
- Web 原型通过 `npm run lint`。
- GitHub 推送成功。

### 待形成持久证据

- 微信隐私保护指引。
- 两个真实账号的家庭共享与跨家庭隔离。
- iOS/Android 真机主流程。
- 微信订阅消息授权、到期推送与点击跳转。
- AppSecret 后续轮换时的函数回归。

### 必测用例

1. 新用户首次进入，自动创建用户和家庭。
2. 添加家庭成员。
3. 拍外包装照片并添加药品，验证列表显示。
4. 新增健康记录。
5. 上传检查单或处方图片，验证云存储 fileId。
6. 进入图片整理确认页，验证结果不会自动写入业务记录。
7. 记录用药，验证库存自动扣减。
8. 创建家庭邀请，另一个用户接受邀请并切换家庭。
9. 进入会员中心，选择优惠券并完成支付确认。
10. 从病程添加健康待办，接受订阅授权并验证到期消息。
11. AI 查询快过期药品。
12. AI 查询诊断类问题，验证拒答。
13. 导出家庭数据和就医沟通记录。
14. Web 管理后台验证统计和列表。

### 结论

自动化、云资源和托管基线已完成；上线结论必须把“代码通过”与“真实发布证据通过”分开报告。
